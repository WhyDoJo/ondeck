# Публикация ondeck на GitHub

В репозиторий отправляются исходники и документация, **не `target/`**.
Локальный кэш может занимать гигабайты, но он уже исключён через `.gitignore`.
Удалять его для публикации не нужно.

Эти команды — инструкция для ручного выполнения. `git commit` сохраняет
историю локально; только `git push` отправляет её на GitHub.

## 1. Подготовь название и README

Ниже используется имя репозитория `ondeck`. В `README.md` замени
`YOUR_USERNAME` на свой GitHub-ник. Если выбрал другое имя репозитория,
поправь также ссылку клонирования и команду `cd`.

Локальная папка может продолжать называться `ondeck`; менять код или имя
бинарника ради имени репозитория не нужно.

## 2. Проверь Git

```sh
cd ~/Documents/dev/ondeck
git status
```

Если Git уже инициализирован, **не повторяй `git init`**. Если получаешь
`not a git repository`, выполни:

```sh
git init -b main
```

Для первой публикации добавь файлы явно:

```sh
git add .gitignore Cargo.toml Cargo.lock LICENSE README.md src docs
git status --short
git diff --cached --stat
```

В commit должны попасть:

```text
.gitignore
Cargo.toml
Cargo.lock
LICENSE
README.md
src/
docs/
```

Не добавляй `target/`, личные доски, логи, секреты или архив всей рабочей папки.
`Cargo.lock` — часть проекта, его исключать не нужно.

### Как убедиться, что кэш не попадёт в GitHub

```sh
git check-ignore target/release/ondeck
git ls-files target
```

Первая команда должна вывести путь, вторая — **ничего**.
Пустой вывод второй команды означает, что файлы `target/` не отслеживаются.
`.gitignore` также исключает `dist/` с подготовленными релизами, `board.json`
в корне, локальные папки `boards/` и `screenshots/`, `.env` и логи.

Другие личные JSON-файлы не становятся автоматически безопасными для публикации:
всегда просматривай список добавленных файлов. Штатная доска обычно хранится
в `~/.local/share/ondeck/`, вне репозитория.

## 3. Первый commit

```sh
git commit -m "Initial release of ondeck"
git branch -M main
```

`git branch -M main` здесь задаёт имя основной ветки для нового проекта.
Не выполняй такой шаг вслепую в чужом или уже существующем репозитории с историей.

Если Git просит автора, настрой его локально для этого проекта:

```sh
git config user.name "Твоё имя или ник"
git config user.email "Твой email для GitHub"
```

Затем повтори commit. Email станет частью истории. Если не хочешь публиковать
личный адрес, возьми свой noreply-адрес в GitHub **Settings → Emails**.

## 4. Пустой репозиторий на GitHub

На GitHub выбери **New repository**:

1. Укажи имя, например `ondeck`.
2. Выбери Public или Private.
3. Не добавляй README, `.gitignore` и лицензию через форму: они уже есть локально.
4. Нажми **Create repository**.

Команду GitHub `echo "# ..." >> README.md` выполнять не нужно — README уже готов.

## 5. Отправка

Замени имя пользователя и при необходимости имя репозитория:

```sh
git remote add origin https://github.com/YOUR_USERNAME/ondeck.git
git push -u origin main
```

Если `origin` уже есть, проверь `git remote -v` и убедись, что это нужный
репозиторий. Не меняй адрес и не делай force push вслепую.

GitHub не принимает обычный пароль аккаунта для Git по HTTPS. Используй
поддерживаемый способ авторизации: credential manager/GitHub CLI, personal
access token или заранее настроенный SSH. Не записывай токен в README, URL
репозитория или другие файлы проекта.

## Дальнейшие изменения

Например, после обновления документации:

```sh
git status
git add README.md docs
git diff --cached --stat
git commit -m "Update documentation"
git push
```

Добавляй только нужные изменения. Повторные `git init` и `git remote add`
для каждого обновления не требуются.

## Если `target/` уже отслеживается

`.gitignore` не убирает из Git ранее добавленные файлы. В таком случае:

```sh
git rm -r --cached -- target
git status
```

`--cached` оставляет локальные файлы на месте, но удаляет их из индекса Git.
После проверки создай commit. Однако большие файлы сохранятся в прошлых
коммитах, если уже были туда записаны. Очистка истории — отдельная операция;
не переписывай её и не используй force push без понимания последствий.

## Как дать пользователям готовую программу

Не добавляй бинарник и кэш в исходники. Прикрепи архив с программой к
**GitHub Release**: [пошаговая инструкция](RELEASING.md).

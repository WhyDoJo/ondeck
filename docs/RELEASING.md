# Релиз с готовой программой

GitHub Release позволяет прикрепить готовый бинарник отдельно от исходников.
Пользователям такого архива не нужны Rust, Cargo и компиляция, но нужны
совместимая Linux-система, системные библиотеки, графическая сессия и GPU-драйвер.

Ниже — пример **нативной сборки Linux x86_64** версии `0.1.0`. Имя архива —
это обозначение платформы, а не команда кросс-компиляции. Не называй сборку
`x86_64`, если она создана для другой архитектуры.

## 1. Проверь и собери

Из папки проекта:

```sh
cargo test --locked
cargo build --release --locked
file target/release/ondeck
```

Для архива из примера `file` должен показывать Linux ELF x86-64.
Перед релизом проверь рисование, сохранение и повторное открытие на временной
доске, чтобы не затронуть личные заметки:

```sh
./target/release/ondeck /tmp/ondeck-release-check.json
```

Проверь `Ctrl+S`, штатное закрытие и повторный запуск с тем же путём.
Если этот временный файл уже существует и тебе нужен чистый тест, выбери другое имя.

## 2. Подготовь архив

Упаковывается только бинарник и лицензия — не `deps/`, не `build/` и не `.d`-файл:

```sh
mkdir -p dist/ondeck-v0.1.0-linux-x86_64
install -m755 target/release/ondeck dist/ondeck-v0.1.0-linux-x86_64/ondeck
install -m644 LICENSE dist/ondeck-v0.1.0-linux-x86_64/LICENSE
tar -czf dist/ondeck-v0.1.0-linux-x86_64.tar.gz -C dist ondeck-v0.1.0-linux-x86_64
```

Архив сохраняет разрешение на запуск программы. Папка `dist/` исключена
через `.gitignore`: **не нужно делать `git add` для релизного архива**.

При желании создай контрольную сумму:

```sh
sha256sum dist/ondeck-v0.1.0-linux-x86_64.tar.gz > dist/ondeck-v0.1.0-linux-x86_64.tar.gz.sha256
```

## 3. Создай GitHub Release

Сначала отправь исходники нужной версии в GitHub. Затем в репозитории:

1. Открой **Releases → Draft a new release**.
2. Нажми **Select tag**, введи `v0.1.0` и выбери создание тега при публикации.
3. В **Target** выбери ветку или commit, из которого собран бинарник.
4. Название релиза: `ondeck v0.1.0`.
5. Прикрепи `dist/ondeck-v0.1.0-linux-x86_64.tar.gz` и, если создавал, файл `.sha256`.
6. Добавь описание и нажми **Publish release**.

**Тег и название релиза — разные поля.** Ввод названия `ondeck v0.1.0`
не создаёт тег автоматически. Ошибка `tag name can't be blank` означает,
что тег нужно отдельно выбрать или создать.

Если тег `v0.1.0` уже существует, не передвигай его на другой commit ради
изменённой сборки: для нового выпуска используй новую версию/тег.

## Пример описания релиза

Адаптируй текст под окружение, на котором **действительно проверил** программу:

> Минималистичная доска для Linux x86_64: перо, ластик, панорамирование,
> масштабирование, undo/redo и сохранение в JSON.
>
> Сборка проверена на Arch Linux + Hyprland/Wayland. Нужны системные
> библиотеки и рабочий GPU-драйвер; рекомендуемый графический путь — Vulkan.
> Rust и Cargo для запуска готового бинарника не требуются.

Инструкции запуска для скачавшего архив:

```sh
tar -xzf ondeck-v0.1.0-linux-x86_64.tar.gz
cd ondeck-v0.1.0-linux-x86_64
./ondeck
```

Чтобы выбрать отдельную доску:

```sh
./ondeck ~/notes/ideas.json
```

## Важные ограничения сборки

- Нативный Linux-бинарник не запускается как приложение Windows/macOS.
- Сборка x86_64 не предназначена для ARM.
- Сборка на свежем Arch может не работать на старых дистрибутивах из-за
  версий glibc и других библиотек. Это не полностью автономный AppImage.
- Драйвер видеокарты и графическая сессия в архив не входят.
- Личные JSON-доски, пользовательские настройки и сборочный кэш не включаются.

Исходники остаются основным вариантом для пользователей другого окружения:
они могут собрать приложение под свою систему по [README](../README.md).

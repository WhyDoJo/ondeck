**ondeck** — быстрый холст для набросков, объяснений и заметок от руки.
Светлая точечная сетка, тёмная панель инструментов и одно безрамное окно:
ничего лишнего между тобой и рисунком.

Это **самостоятельная доска**, а не прозрачный оверлей для рисования поверх
других приложений. Основной сценарий использования — Arch Linux + Hyprland/Wayland.

## Возможности

- Холст без фиксированного размера страницы, с перемещением и масштабированием.
- Свободное рисование со сглаживанием штрихов.
- Пять цветов и три толщины пера.
- Ластик для удаления целых штрихов.
- Отмена, повтор и очистка; история до 200 действий.
- Масштабирование к курсору в диапазоне **20–800%**.
- Сохранение доски в JSON и открытие ранее сохранённой доски.
- Открытие файла перетаскиванием в окно.
- Собственная компактная панель с подсказками при наведении.
- GPU-отрисовка без Electron и браузерного интерфейса.

## Установка

### 1. Зависимости на Arch Linux

```sh
sudo pacman -S --needed base-devel git pkgconf wayland libxkbcommon vulkan-icd-loader
```

Если Rust ещё не установлен:

```sh
sudo pacman -S --needed rust
```

Если уже используешь **rustup**, оставь его и используй актуальный stable toolchain;
устанавливать пакет `rust` параллельно не нужно.

Для описанного сценария запуска подготовь рабочий Vulkan-драйвер своей видеокарты:

| Видеокарта | Что нужно |
| --- | --- |
| Intel с поддержкой Vulkan | `vulkan-intel` |
| AMD с поддержкой Vulkan | `vulkan-radeon` |
| NVIDIA | Совместимый с GPU драйвер NVIDIA и соответствующий `nvidia-utils` |

Не устанавливай все драйверы подряд. Если Vulkan-приложения уже работают,
дополнительная установка может не понадобиться. Loader сам по себе не заменяет
драйвер видеокарты. Графический бэкенд выбирает wgpu; совместимость других
бэкендов и окружений здесь не гарантируется.

### 2. Клонирование и сборка

Замени `YOUR_USERNAME` на владельца репозитория. Если репозиторий называется
иначе, поправь также имя в ссылке и команде `cd`.

```sh
git clone https://github.com/YOUR_USERNAME/ondeck.git
cd ondeck
cargo build --release --locked
```

Первый запуск сборки скачает зависимости и создаст кэш в `target/`.
Для обычного использования выбирай **release-сборку**: debug не подходит
для оценки скорости и задержки рисования.

### 3. Установка в домашнюю папку

```sh
install -Dm755 target/release/ondeck "$HOME/.local/bin/ondeck"
```

`sudo` не нужен. Команда устанавливает только бинарник; конфиги Hyprland,
автозапуск и пользовательские доски не меняются. Для вызова `ondeck` без полного
пути каталог `~/.local/bin` должен быть в `PATH`.

> Установка необязательна: из папки проекта можно запускать
> `./target/release/ondeck`. После `cargo clean` этот файл придётся собрать заново.

## Запуск

Из терминала своей графической сессии, без `sudo`:

```sh
~/.local/bin/ondeck
```

Откроется обычное безрамное окно с доской. Оно не требует layer-shell и не
перехватывает весь рабочий стол, как экранный оверлей.

Без аргумента используется стандартная доска. Чтобы открыть другую или создать
новую, передай путь к JSON-файлу:

```sh
~/.local/bin/ondeck ~/notes/ideas.json
~/.local/bin/ondeck ~/notes/lesson.json
```

Если файл ещё не существует, доска начинает работу пустой и создаёт его при
сохранении. Родительские папки создаются автоматически. Можно также перетащить
сохранённый файл в окно — **перед переключением сохрани текущую доску**.

Справка по командной строке:

```sh
~/.local/bin/ondeck --help
```

> Здесь нет команды `toggle` и механизма единственного экземпляра.
> Каждый запуск открывает отдельное окно. Не открывай один JSON-файл в нескольких
> окнах для одновременного редактирования: сохранение одного окна может затереть
> изменения другого.

## Управление

| Действие | Клавиши / мышь |
| --- | --- |
| Рисовать | Левая кнопка мыши |
| Перо / ластик | `P` / `E` |
| Перемещать холст | Удерживать `Space` и тянуть левой кнопкой либо тянуть средней кнопкой |
| Масштабировать к курсору | Колесо мыши |
| Сбросить вид к исходному центру и масштабу | `Ctrl+0` |
| Отменить | `Ctrl+Z` |
| Повторить | `Ctrl+Shift+Z` или `Ctrl+Y` |
| Выбрать цвет | `1`–`5` |
| Уменьшить / увеличить толщину | `[` / `]` |
| Сохранить | `Ctrl+S` |
| Отменить текущий жест рисования или стирания | `Esc` |
| Закрыть | `Ctrl+W` или точка справа на панели |

На панели также есть кнопки отмены, повтора и очистки. **Очистку можно отменить.**
Ластик удаляет целые штрихи, а не отдельные пиксели. Сочетания привязаны
к физическим клавишам, поэтому не зависят от выбранной раскладки букв.

Окно можно перемещать за свободную часть тёмной панели и менять его размер за
края. Системного заголовка и крестика нет. В Hyprland поведение перемещения
и ресайза также зависит от того, находится окно в плавающем или плиточном режиме.

## Сохранение и файлы

По умолчанию доска хранится здесь:

```text
$XDG_DATA_HOME/ondeck/board.json
```

Если `XDG_DATA_HOME` не задан, обычно это:

```text
~/.local/share/ondeck/board.json
```

В файле сохраняются штрихи, их цвет и толщина, а также положение и масштаб камеры.
История undo/redo и выбранный инструмент между запусками не сохраняются.

### Когда записываются изменения

- **`Ctrl+S`** сохраняет текущее состояние доски и камеры.
- **Штатное закрытие окна** сохраняет доску, если были правки документа.
- Одно только перемещение или масштабирование камеры не отмечает документ
  изменённым: чтобы точно сохранить новый вид, нажми `Ctrl+S`.
- Сохранения по таймеру, резервных копий и гарантированного восстановления
  после аварийного завершения нет. Для важных заметок сохраняйся вручную.

При ошибке записи появляется `save failed`, подробности выводятся в терминал.
При закрытии ошибка сохранения также пишется в терминал, но окно всё равно
закрывается — лучше заранее убедиться, что `Ctrl+S` отработал успешно.

Если файл не удалось открыть, приложение показывает `open failed` и не
перезаписывает его автоматически при выходе. **Явный `Ctrl+S` может заменить
такой файл**, поэтому сначала сделай его копию и проверь причину ошибки.

Перетаскивание другого файла заменяет текущую доску в окне без предварительного
автоматического сохранения. Сначала нажми `Ctrl+S`.

## Хоткеи Hyprland

Пример запуска по **`Super+Ctrl+B`**. Проверь, что сочетание не занято в твоём
конфиге. Автозапуск не нужен, глобального хоткея достаточно.

### Конфиг `.conf`

Добавь в свой файл биндов или `~/.config/hypr/hyprland.conf`:

```ini
$ondeck = ~/.local/bin/ondeck
bind = SUPER CTRL, B, exec, $ondeck
```

Для отдельной доски вместо стандартной:

```ini
bind = SUPER CTRL, B, exec, ~/.local/bin/ondeck ~/notes/ideas.json
```

Это два варианта одного бинда — выбери один, не добавляй оба на одно сочетание.

### Lua-конфиг с `hl.bind`

Если твой Hyprland использует API `hl.bind` / `hl.dsp.exec_cmd`, добавь в
загружаемый модуль биндов:

```lua
local ondeck = os.getenv("HOME") .. "/.local/bin/ondeck"
hl.bind("SUPER + CTRL + B", hl.dsp.exec_cmd(ondeck))
```

Используй пример под свой формат конфигурации. Затем примени изменения:

```sh
hyprctl reload
```

Повторное нажатие запускает **ещё одно окно**, а не показывает или скрывает
существующее. Перед новым запуском закрой старое, если работаешь с той же доской.

## Производительность и ограничения

- Rust, winit и wgpu; штрихи, сетка и интерфейс отрисовываются через WGSL-шейдеры.
- Геометрия завершённых штрихов кэшируется и обновляется при изменении документа.
- Активный штрих рисуется отдельно; используется instanced rendering.
- В простое цикл событий ждёт событий, а не непрерывно генерирует кадры.
- Запрашивается `HighPerformance` GPU; фактическое потребление и задержка
  зависят от устройства, драйвера и размера доски.

Пока есть только свободное перо и ластик: нет текста, отдельных инструментов
фигур/стрелок, экспорта PNG/SVG, совместного редактирования или синхронизации.
JSON — внутренний формат доски, не изображение. Совместимость с любым Linux,
Windows/macOS или всеми GPU не заявляется.

## Решение проблем

**Окно не открывается.** Запускай из терминала внутри графической сессии без
`sudo`, смотри сообщение об ошибке. Для Wayland должны быть доступны
`WAYLAND_DISPLAY` и `XDG_RUNTIME_DIR`.

**Не найден GPU или ошибка Vulkan.** Проверь драйвер своей видеокарты.
Для диагностики можно установить `vulkan-tools` и выполнить `vulkaninfo --summary`.
Само наличие Vulkan loader ещё не означает, что драйвер установлен правильно.

**Рисование тормозит при разработке.** Сначала собери `--release` и проверь
`target/release/ondeck`. Скорость debug-сборки не показатель скорости приложения.

**Не найден файл доски.** Проверь, не задан ли `XDG_DATA_HOME` и не был ли передан
отдельный путь при запуске. Разные пути — разные доски.

**`save failed` / `open failed`.** Проверь права на файл/папку, свободное место
и формат JSON. Не перезаписывай важный файл, пока не сделал резервную копию.

**Бинд не работает.** Проверь путь к бинарнику, формат конфига, конфликты клавиш
и вывод `hyprctl configerrors` после reload.

## Разработка

```sh
cargo test --locked
cargo build --release --locked
```

```text
src/main.rs            Окно, ввод, жесты и цикл событий
src/document.rs        Документ, история, загрузка и сохранение
src/draw.rs            Камера, геометрия, сглаживание и hit testing
src/gpu.rs             GPU-рендерер и буферы
src/ui.rs              Панель, подсказки и её геометрия
src/shaders/           WGSL: штрихи, точечная сетка и интерфейс
```

`Cargo.lock` хранится в Git, чтобы фиксировать версии зависимостей приложения.
`publish = false` в `Cargo.toml` запрещает публикацию пакета на crates.io,
но **не мешает GitHub-репозиторию и GitHub Releases**.

### Почему `target/` занимает гигабайты?

Это кэш сборки, зависимости, тестовые бинарники и промежуточные файлы,
а не исходники. Он исключён через `.gitignore` и не нужен в GitHub.
Удалять его ради публикации не нужно.

`cargo clean` удалит кэш **и `target/release/ondeck`**. Установленная отдельно
копия в `~/.local/bin/ondeck` и доски в пользовательской папке данных останутся.

## Удаление

Закрой приложение и удали установленный вручную бинарник:

```sh
rm -- "$HOME/.local/bin/ondeck"
```

Добавленный бинд убери из конфига Hyprland отдельно. Доски не удаляются:
они остаются по своим JSON-путям.
